# Stakeholder Analysis & Governance

## Stakeholder register

| Stakeholder | Interest / responsibility | Influence | Engagement |
|---|---|---|---|
| Executive sponsor / COO | Outcomes, funding, escalation | High | Steering committee |
| General Counsel | Legal policy, clause standards, legal sign-off | High | Design authority |
| Procurement Director | Supplier process, vendor contracts | High | Process workshops |
| Finance Controller | Financial controls and thresholds | High | Approval-rule workshops |
| Sales Operations | Customer agreements and turnaround | Medium | User workshops |
| HR Operations | Employment agreement process | Medium | Restricted-scope workshops |
| IT Applications | Architecture, integrations, support | High | Technical design |
| Information Security | Access, risk, controls | High | Security review |
| Contract owners | Intake, metadata and obligations | Medium | Interviews and UAT |
| Approvers | Review tasks and decisions | Medium | Workflow validation |

## RACI (illustrative)

R = Responsible, A = Accountable, C = Consulted, I = Informed.

| Activity | Sponsor | Legal | Procurement | Finance | IT | Functional consultant |
|---|---|---|---|---|---|---|
| Scope approval | A | C | C | C | C | R |
| Legal clause policy | I | A/R | C | I | I | C |
| Procurement process | I | C | A/R | C | I | C |
| Approval threshold | I | C | C | A/R | I | C |
| Solution design | I | A | C | C | R | R |
| Migration validation | I | C | A/R | C | R | R |
| UAT sign-off | I | A | R | R | C | C |
| Go-live approval | A | C | C | C | R | C |

## Governance cadence

- Weekly workstream meeting: requirements, decisions, risks and dependencies.
- Fortnightly design authority: workflow, metadata, security and integration decisions.
- Steering committee at key gates: scope, design, UAT and go-live.
- Decision log: owner, decision, rationale, date and impacted requirement.
- RAID log: risks, assumptions, issues and dependencies with owner and due date.

## Change control

Every change request should record the requested change, business rationale, impacted requirements, configuration/data/testing impacts, effort and risk, decision authority, approval status and version.
